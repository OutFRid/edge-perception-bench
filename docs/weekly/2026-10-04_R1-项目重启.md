## 目标① 环境复现（已完成）
停摆两月后板端环境漂移，逐项修复并**经一次冷启动验证持久性**：
- SSH 断链：Windows 侧 ICS 误配在「本地连接 2」上导致其掉到 APIPA；改回静态 `192.168.137.1/24`，并把 ICS 正确配到 WLAN → SSH 恢复、板端出网打通。
- 产物丢失根因：外置 SSD `/dev/sda1`（ext4，UUID `ac9d91be-…`）未挂载，模型/DMD 数据都在其上。已写入 `/etc/fstab`（`nofail,x-systemd.automount`），重启后首访自动挂载，`acl_diag.py` 加载 OM `ret=0`。
- 依赖丢失根因：系统 Python 由 3.9.2 被重置为 3.10，numpy/cv2/onnxruntime/pip 全丢。apt 装 `python3-numpy python3-opencv python3-pip`，pip 装 `onnxruntime`；踩坑：onnxruntime 会把 numpy 顶到 2.x 打坏 apt 版 opencv，已 `pip install 'numpy<2'` 回退 1.26.4。
- 连板通道固化：`~/.ssh/config` 增 `ascend-dk` + ed25519 独立密钥实现**免密直连**；板端 usb0 静态 IP `192.168.137.2` 由常驻 watchdog（`scripts/board/dk-usb0-fix`）持久化，重启/拔插/断电后自愈。根因与方案见 `docs/DK网络持久化配置.md` 及同名博客。

## 目标② 框偏移修复（已完成）
**真实根因（纠正 7-20 归档文档 §5.1 的归因）**：不是 mosaic/分辨率问题，而是 `infer_yolo_acl.py` 的**坐标反变换缺失**——预处理把 1280×720 直接 `resize` 成 640×640 正方形（拉变形），后处理输出的却是 640 空间的框，`main()` 又把这些框**直接画到 1280×720 原图**，故整体偏移且尺寸错。附带 bug：`cv2.dnn.NMSBoxes` 需要 `[x,y,w,h]`，旧代码喂的是 `[x1,y1,x2,y2]`。

**修复**：
1. 预处理改 letterbox（保比例 + 居中补边），返回 `ratio` 与 `pad`；
2. 后处理把框从 640 letterbox 空间逆映射回原图坐标（去 pad、除 ratio、clip）；
3. NMS 入参改 `[x,y,w,h]`。

**验证**：同一 mosaic 首帧，person 框由旧版 `[95.5,381.5,263.2,639.5]`（640 空间）修正为 `[166.5,437.0,523.0,715.0]`（原图空间），肉眼框住驾驶员；latency 27.1ms。`tv 0.32` 为 COCO 模型对车窗的误检，属模型类别限制，非坐标问题（真做 DMS 应按 §5.2 换人脸模型 + face.mp4，留待 R2/R3）。
