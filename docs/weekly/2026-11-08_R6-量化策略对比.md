## 三条认知（本周敲实）
1. **全网络量化是检测模型的坑（S6 铁证）**：S6 量化全部算子后 cosine 仍 0.998，但**检出数=0**——量化后的 Softmax/Reshape/Concat 等节点破坏了检测头输出。**张量级 cosine 高 ≠ 检测语义可用**，再次证明精度必须分层报（R5 认知②升级为方法论）。
2. **CPU 上不存在「更快的量化策略」**：7 组策略延时 71~100ms，除 S7（≈FP32 等价物）外全部慢于 FP32 1.2~1.35×。策略间的延时差异 ≤12%，本质是「多插的 Q/DQ 节点开销」而非策略优劣。**量化延时收益是硬件属性，策略选择在无 int8 MAC 的硬件上对延时无效**——与 R5 认知①互证。
3. **上板策略已可拍板**：若 NPU INT8 链打通，选 **S3（Percentile / per-channel / Conv+MatMul）**——精度最稳（conf 最高 0.716、IoU vs S1=0.965），并显式排除检测头敏感算子（S6 教训）。per-channel 全面优于 per-tensor（IoU 0.965 vs 0.893）。

## 遇到阻碍 / 遗留问题
- **AMCT 包无法自动获取**：昇腾 AMCT（`Ascend-cann-amct_7.0.x_linux-x86_64.zip`，含 `amct_onnx` whl + custom op 注册包）只在昇腾社区官网发布，下载需登录 + 签名 URL；gitee 无 `ascend/amct` 镜像（搜索为空）；OBS 直链 403。→ **需人工从官网下载**（登录后 CANN 7.0.1 下载页选 AMCT 包）。
- **WSL CANN 7.0.1 ATC 同样拒绝 onnxruntime 产 QDQ ONNX**：实测 `No parser is registered for Op QuantizeLinear/DequantizeLinear`，与板端 7.0.RC1 行为一致。结论：**「QDQ ONNX→ATC」在此 CANN 代际不可行**，唯一官方路径 = AMCT 产出 QDQ + amct custom op 注册 → ATC。
- 遗留转 R8 缓冲周：拿到 AMCT 包后，用 R6 拍板的 S3 策略 + 同一标定/评测口径产出真·NPU INT8 OM，补「NPU INT8 延时收益 + 上板精度」。
