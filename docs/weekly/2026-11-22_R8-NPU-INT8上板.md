# R8 · 主题：缓冲/补漏周——NPU INT8 上板（延时收益坐实，精度未达标）

> 日期区间：2026-11-22 ~ 2026-11-28
> 状态：✅ 完成（链打通 + 延时收益坐实；**精度不达标，根因已定位，修复被 310B 硬件限制阻断，不粉饰**）

## 本周目标（≤3 个）
1. ☑ 人工获取 AMCT 包 → WSL modelslim PTQ（S3 策略）产 INT8 ONNX → ATC 离线编 OM → 上传板端跑通。
2. ☑ 板端双口径评估：纯推理延时基准（FP32 vs INT8）+ DMD 16 帧精度对照（输出 cosine / 检出 / person conf / 匹配 IoU，同 R5 口径）。
3. ☑ 精度退化定位：逐层中间特征对照找退化层 → 假设验证 → 修复尝试（v3~v7 共 5 版图），结论如实归档。

## 背景
- 承 R6 周志：NPU INT8 上板因 AMCT 包不可得顺延至本缓冲周；R5 只完成了 CPU 口径（INT8 反而慢 1.3×，量化收益是硬件属性），板端口径收益未验证。
- 承 R4 结论「310B 上 yolov8n 访存/搬运 bound」——INT8 的 I/O 减半对搬运 bound 的模型收益预期可观。

## 核心数据一：纯推理延时（200 iters，bench_latency_acl 同口径）

| 口径 | compute ms | h2d ms | d2h ms | 推理合计 ms | fps |
|------|---:|---:|---:|---:|---:|
| FP32 OM | 12.89 | 1.58 | 1.60 | 16.07 | 62.2 |
| INT8 OM (v2) | **10.82** | **0.75** | **1.19** | **12.76** | **78.4** |

- compute **↓16.1%**、推理合计 **↓20.6%**、fps 62.2→78.4；h2d ↓52%（int8 输入 4.9MB→2.5MB 直接减半）。
- **量化延时收益在 NPU 口径坐实**（R5 CPU 口径「INT8 反而慢」的悬念闭合：收益确实是硬件属性）。

## 诊断证据链（四重排除，全部实证）

1. **单层 ATC 链正确**：mini_s7（真实参数单层 q→conv→deq）板端 vs CPU 精确手算 **cos=0.999987**；vs FP32 同层 0.999721 → 单层 int8 链编译执行无误。
2. **图语义正确**：CPU 两层链精确模拟（s7→SiLU→s8_cv1，真实权重/scale）——v2 语义（无输出重量化）cosine **0.99929** ≈ QDQ 语义（有输出重量化）**0.99910** → 「modelslim 丢弃 y_scale 致误差累积」的假说**不成立**，输出重量化修复方向被证伪。
3. **量化策略正确**：CPU QDQ 0.9986 vs 板端 0.9716（同策略）→ 退化非量化本身。
4. **退化模式**：误差非单调累积（s15 回升 0.987），在 s7（stride=2 下采样）与 s8 bottleneck 处跳升 → 指向完整图编译后的执行特性（融合边界精度转换），非逐层均匀漂移。

## 修复尝试与 310B 硬件限制墙（v3~v7 五版图全记录）

| 版本 | 方案 | 结果 |
|------|------|------|
| v3 | 独立 AscendDequant（标量/广播 scale） | ATC 编译失败：`pragma_deq_scale` 仅支持 fp16 输出（mini_f1/f2 证实，与 scale 形状无关） |
| v4 | Mul+Round+Mul 纯 fp32 链模拟重量化 | 编译通过，板端精度**更差**——mini_f5 实测证实 310B 上 fp32 逐元素算子（Mul/Round）**以 fp16 执行**，t=y_fp/sy 大数值下 fp16 ulp 0.5~1 格污染 round 前值 |
| v6 | AscendQuant(int8)+Cast(int8→fp32)+Mul(y_scale) | 数学最优（fp16 ulp 仅 ~0.12 格）但板端**完全崩坏**：int8 张量 trans_data 布局转换在 310B 上结果错乱（mini_f4 编译期 forkserver 崩溃同源） |
| v7 | AscendQuant(dst_type=1，输出 fp32)+Mul | 编译失败：GE InferShapePass `/model.22/Add_1` 报错 |
| v5（最终产物） | 输出重量化链（含 Cast int8→int32 迂回） | 因上述硬件限制未能产出可用 OM（full/mid 编译均失败或非预期） |

- **结论**：v2 的「每层输出截断缺失」在 CPU 数学上并不显著（证据链 2），真实退化源在完整图编译执行侧；而 310B 对独立 quant/dequant/fp32 逐元素算子的四重限制（fp16 强制 / trans_data bug / pragma 限制 / InferShape 失败）封死了软件侧全部修复路径。
