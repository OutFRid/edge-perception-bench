## 目标① DMS 流水线（已完成）→ `scripts/infer_dms_pipeline.py`
把 R1 的单帧脚本 `infer_yolo_acl.py` 重构为**面向阶段的流水线**，对齐参考骨架分层：

| 本项目类 / 阶段 | 职责 | 对应 MindSDK 骨架 | 在跑的地方 |
|---|---|---|---|
| `AclContext` | init/set_device/create_context | `MxInit()` | Host 发起 |
| `AclExecutor` | 载 OM + 执行；**把 H2D / execute / sync / D2H 拆开各自计时** | `Model::Infer()`（内部吞了 sync） | Device |
| `LetterboxPreprocess` | 保比例缩放+补边+NCHW+/255，返回 `ratio/pad` | `DvppPreprocessor`/`OpenCVPreProcessor` | Host |
| `YoloV8Postprocess` | 解码→置信过滤→NMS→**坐标逆映射回原图** | `Yolov7PostProcess::Process` | Host |
| `run_pipeline` | 逐帧流式编排 + 8 段累计计时 + 输出标注视频/单帧/JSON | `main.cpp` Pipeline 编排 | — |

关键设计：换模型时只替 OM 路径与 postprocess 类别/解码，**阶段结构不动**（为 R3 换模型铺好骨架）。

## 目标② 连板实测（已完成）→ 数据流跑通 + 分阶段耗时
runner：`scripts/board/run_r2.sh`（用 glob 解析含 `;` 的 DMD 文件名，规避 PowerShell→bash 转义坑）。
片段：`gA/1/s1/*_mosaic.avi`（1280×720，29.8fps，共 6777 帧，本次取 60 帧）。模型：`model/yolov8n.om`（COCO）。

**首帧即验证数据流正确**：input `(1,3,640,640)` ratio=0.50 pad=(0,140) → output `(1,84,8400)` → person 框 `[124.9,428.0,450.1,717.0]` conf=0.854（逆映射回原图，坐标对得上）。60 帧 person 检出率 100%。

**分段耗时均值（ms/帧，wall-clock）**：

| decode | preprocess | h2d | execute | sync | d2h | postprocess | render | **E2E** |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 7.58 | 21.88 | 8.62 | 12.87 | 0.08 | 1.63 | 29.88 | 61.50 | **144.03** |

吞吐 ≈ 6.94 fps。数据已回填《一帧图的旅程》§9，并导出 `results/doc/dms_gA1s1_stats.json`、标注单帧 `results/image/dms_gA1s1_frame.jpg`。

**三条被数据敲实的认知（R1 心智模型的验收）**：
1. **Host CPU 才是单帧延时大头**：`preprocess+postprocess=51.8ms` ≫ NPU 侧 `execute+sync+拷贝=23.2ms`。印证 §7 预判「预处理可能比 NPU 计算还久」——优化不能只盯 NPU，R7（DVPP 替 OpenCV）的正主就是这里。
2. **R1 报的 27ms ≠ 端到端**：那只是 H2D+execute+sync+D2H；端到端含渲染 144ms，去渲染仍约 82ms。读延时的坑彻底讲清了。
3. **execute/sync 的分离**证明 execute 是异步入队、sync 才是真栅栏；本次 sync 仅 0.08ms 说明采样时设备已近算完。
