## 1. R1 · 环境复现 + 第一帧框偏修复

### 1.1 一句话结论
> 停摆两月后板端会「环境漂移」（IP 掉线、产物未挂载、Python 被重置），修的是**可复现性**；
> 框偏移不是模型问题，是**坐标空间没对齐**——前处理把图拉成 640×640，后处理却把 640 空间的框直接画到 1280×720。

### 1.2 核心知识点

**A. 坐标系三次搬运（框偏移的真正考点）**
```
原图 1280×720
  │ ① 前处理 letterbox：r=min(640/720,640/1280)=0.5 → 640×360，居中补边 pad_top=140,pad_left=0
  ▼
letterbox 640×640 空间（模型输入 = 模型输出框所在空间）
  │ ② NPU 推理（只挪数字，不懂坐标语义）
  ▼
输出框仍在 640 空间
  │ ③ 后处理逆映射：x_原=(x_框-pad_left)/r；y_原=(y_框-pad_top)/r；再 clip
  ▼
原图坐标 → 才能正确画回 720×1280
```
- 记忆点：**前处理记的 `ratio/pad` 是逆映射的唯一线索，这步不记，后处理必歪。**
- 自检算例：letterbox 框 `[83.25,358.5,261.5,497.5]`，r=0.5,pad_top=140 → 原图 `[166.5,437.0,523.0,715.0]`。

**B. 三个修复动作**
1. 预处理 `resize` 改 **letterbox**（保比例+补边），返回 `ratio` 与 `pad`；
2. 后处理把框从 640 空间**逆映射**回原图（去 pad、除 ratio、clip）；
3. `cv2.dnn.NMSBoxes` 入参必须是 **`[x,y,w,h]`**，旧代码喂了 `[x1,y1,x2,y2]`（附带 bug）。

**C. 环境漂移根因分类（排查方法论）**
| 症状 | 根因层 | 修复 |
|------|------|------|
| SSH 断链 | Windows ICS 误配掉到 APIPA | ICS 正确配到 WLAN，静态 `192.168.137.1/24` |
| 产物丢失 | 外置 SSD `/dev/sda1` 未挂载 | 写 `/etc/fstab`（`nofail,x-systemd.automount`） |
| 依赖丢失 | 系统 Python 被重置，numpy/cv2 丢 | apt 装 python3-numpy/opencv/pip；`pip 'numpy<2'` 回退（onnxruntime 会顶到 2.x 打坏 opencv） |
| 连板不稳 | usb0 IP 重启后被覆盖 | 常驻 watchdog `scripts/board/dk-usb0-fix` 持久化 `192.168.137.2` |

### 1.3 自测问题
1. 为什么直接 `resize` 到正方形会导致框歪？letterbox 补的边为什么要记 `pad`？
2. `NMSBoxes` 要什么格式的框？喂错成 `[x1,y1,x2,y2]` 会怎样？
3. 板端冷启动后 usb0 掉 IP，为什么用「常驻 watchdog」而不是「开机跑一次脚本」？

## 2. R2 · DMS 流水线 + ACL 数据流连板实测

### 2.1 一句话结论
> 把单帧脚本拆成**面向阶段的流水线**，逐帧流式跑真实 DMD 片段并**分段计时**，
> 用数据证明：**端到端 144ms 里，NPU 计算只占约 23ms，Host 前后处理才是大头。**

### 2.2 流水线分层（仿 MindSDK YOLOv7Detection 骨架）
| 本项目类 | 职责 | 对应 MindSDK | 在哪跑 |
|------|------|------|------|
| `AclContext` | init/set_device/create_context | `MxInit()` | Host 发起 |
| `AclExecutor` | 载 OM + 执行；**H2D/execute/sync/D2H 拆开计时** | `Model::Infer()` | Device |
| `LetterboxPreprocess` | 保比例缩放+补边+NCHW+/255，返回 ratio/pad | `DvppPreprocessor` | Host |
| `YoloV8Postprocess` | 解码→置信过滤→NMS→逆映射 | `Yolov7PostProcess` | Host |
| `run_pipeline` | 逐帧编排 + 8 段累计计时 + 输出 | `main.cpp` 编排 | — |

### 2.3 完整数据流（8 阶段 + Host/Device 边界）
```
Decode → Preprocess → [H2D] → Execute → Sync → [D2H] → Postprocess → Render
 └──────── Host CPU ────────┘   └── 跨总线 ──┘  └──── Device ────  └─ 跨总线 ─┘ ──── Host CPU ────┘
```
- **两条跨总线通道**：H2D（进）、D2H（出）——Host 与 Device 唯一数据交换。
- **一个栅栏**：`mdl.execute` 只是**异步入队**，返回 ≠ 算完；读输出前必须 `synchronize_stream`，否则拷回脏数据/全 0。
- 张量形状记忆：**进 `1×3×640×640`（NCHW,float,0~1），出 `1×84×8400`**（84=4框+80类，8400=候选框数）。

### 2.4 实测分段耗时（60 帧均值，DMD gA/1/s1 mosaic，yolov8n.om）
| 阶段 | ms/帧 | 占比 | 在哪跑 |
|------|---:|---:|------|
| decode | 7.58 | 5.3% | Host |
| **preprocess** | **21.88** | **15.2%** | Host |
| h2d | 8.62 | 6.0% | 跨总线 |
| execute | 12.87 | 8.9% | Device |
| sync | 0.08 | 0.1% | Device→Host |
| d2h | 1.63 | 1.1% | 跨总线 |
| **postprocess** | **29.88** | **20.7%** | Host |
| render 写视频 | 61.50 | 42.7% | Host（纯基准应扣除） |
| **E2E** | **144.03** | — | ≈6.94 fps |

**三条被数据敲实的认知**：
1. `preprocess+postprocess=51.8ms` ≫ `execute+sync+拷贝=23.2ms` → 优化不能只盯 NPU，**R7 用 DVPP 替 OpenCV 预处理**正是冲这来的。
2. R1 报的 27ms 只是「推理调用」（H2D+execute+sync+D2H），**不是端到端**；去渲染仍约 82ms。
3. D2H 比想象快（输出连续拷贝仅 1.6ms），H2D 比想象贵（输入 3MB + `ascontiguousarray` 化 8.6ms）。

## 3. R3 · 换模型跑基准（本周计划）

### 3.1 一句话结论
> 流水线骨架已就位，换模型只需**替 OM 路径 + 改 postprocess 的类别/解码**，阶段结构不动。

### 3.2 换模型要动的地方（对照 `infer_dms_pipeline.py`）
| 环节 | 换模型时 | 说明 |
|------|------|------|
| OM | ATC 重新编译：ONNX→OM→上传板端 | `--om` 指向新模型 |
| Preprocess | 视模型输入尺寸/归一化调整 | 若仍 640 letterbox 可不动 |
| Postprocess | **必改**：输出布局、类别数、解码方式 | YOLOv8 的 `(1,84,8400)` 是特定布局 |
| 坐标逆映射 | 保持与前处理 ratio/pad 一致 | 换模型也别忘逆映射（R1 的坑） |

### 3.3 方向要先定（口径陷阱）
- **MobileNetV3-Small 是分类模型**，输出是类别概率，没有框——只能对比「分类 vs 检测」的**延时**，不能直接进检测基准。
- 若要贴 DMS 语义，应按 `first-frame` §5.2 换**人脸/驾驶状态检测模型**（DMD 有 `rgb_face.mp4` 可用）。
- → R3 第一步先拍板：这轮是「分类 vs 检测延时对比」还是「检测模型间对比」。

### 3.4 自测问题
1. 换 MobileNetV3-Small 后，postprocess 还能用 YOLOv8 的解码吗？为什么？
2. 分类模型能算 mAP 吗？它和检测模型的「精度」口径差别在哪？

## 4. 术语速查表
| 术语 | 含义 |
|------|------|
| ACL | Ascend Computing Language，昇腾底层计算 API |
| OM | 昇腾离线编译后的模型（ATC 把 ONNX 编成 NPU 指令） |
| ATC | Ascend Tensor Compiler，ONNX→OM 编译工具 |
| AI Core | NPU 上真正跑模型的计算单元 |
| DVPP | NPU 上的图像/编解码加速单元（可替 Host 做预处理） |
| H2D / D2H | Host↔Device 内存拷贝（跨 PCIe/总线） |
| letterbox | 保比例缩放 + 补边到固定尺寸 |
| NMS | 非极大值抑制，去重叠框 |
| synchronize_stream | 等待 stream 上异步任务真正算完的栅栏 |
| DMS | Driver Monitoring System，驾驶监控系统 |
| DMD2 | 公开驾驶监控数据集（face/body/hands/mosaic + 标注） |

## 5. 动手复现清单（连板）
```bash
# 0) Windows 侧确认 ICS 配到 WLAN、板端 usb0=192.168.137.2（掉线跑 dk-usb0-fix）
ssh ascend-dk "npu-smi info"                       # 1) 板子与 NPU 健康

# 2) 环境自检（务必先 source set_env.sh）
ssh ascend-dk "source /usr/local/Ascend/ascend-toolkit/set_env.sh && python3 /root/epb/scripts/acl_diag.py"

# 3) 跑 R2 流水线（glob 解析含分号的 DMD 文件名，避开 PowerShell 转义坑）
ssh ascend-dk "bash /root/epb/scripts/run_r2.sh"

# 4) 单帧框偏复现（R1）
ssh ascend-dk "source .../set_env.sh && python3 /root/epb/scripts/infer_yolo_acl.py \
    --om /mnt/e61/workspace/dmd/model/yolov8n.om --video <mosaic.avi> --save /tmp/f.jpg"
```
> 板端布局：代码 `/root/epb/scripts/`，产物 `/root/epb/results/`，DMD2 数据 `/mnt/e61/workspace/dmd/`。
> PowerShell→ssh→bash 传命令：引号/`$()`/分号文件名易被 PowerShell 误解析，复杂命令一律 **scp 一个 .sh 上板再 bash 跑**。
