| # | 问题 | 我的回答（要点） | 标准答案（满分表述） | 判定 | 盲区订正 |
|:-:|------|------|------|:-:|------|
| 1 | 为什么直接 `resize` 成正方形会让框歪？letterbox 补的边为什么要记 `pad`？ | 硬拉伸 1280×720→640×640 破坏长宽比→几何变形、精度下降；且未记录缩放参数，后处理无法把 640 空间的框逆映射回原图→整体偏移。必须 letterbox + 记 ratio/pad 反变换。 | **两个独立 bug，分开归因**：①**失真**（破坏纵横比→模型见变形图→精度降）；②**偏移**（没记 ratio/pad 且把 640 坐标"直接画"到原图）。逆变换数学上一直可做（硬拉伸只要老实记 `sx,sy` 也能还原），致命处在"没记 + 直接画"。letterbox 同时赢两点：**不失真**（精度）+ **逆映射最简**（单个 `r` + 一个 `pad` 通吃 xy）。 | ✅ | 初答把"变形"与"无法逆映射"捆成一句；已拆成 **失真 / 偏移** 独立归因。 |
| 2 | `NMSBoxes` 要 `[x,y,w,h]`，旧代码喂了 `[x1,y1,x2,y2]`，为什么会出问题？后果？ | 喂错会让框"异常大"（横纵坐标被当成宽高），"就不是 anchor-free 了"。 | `NMSBoxes` 按位置硬读：`x1→x`✅ `y1→y`✅ **`x2→宽w`❌ `y2→高h`❌** → 框右边界被算成 `x1+x2`，**撑大一截**。NMS 用两两 **IoU** 判重复框：框虚胖 → 重叠面积虚高 → **IoU 虚高 → 过度抑制 → 该留的邻近目标被误删（漏检）**。**画出的框坐标其实没错**（单独存了 `x1y1x2y2`），错的是 NMS"保留哪几个"的决策。修复：喂 `[x1, y1, x2-x1, y2-y1]`。 | ⚠️ | 两处：①后果误判为"画出来歪"，实为 **NMS 决策错**；②把"IoU/预设框"当成 anchor-based——见下方追问澄清。 |
| 3 | 板子冷启动 usb0 掉 IP，为什么用常驻 watchdog 而不是开机跑一次脚本？ | 开机后板子固件有个操作，在常用网络配置**之后**把 IP 改回去，所以一次性设不够，要 watchdog 守着。 | 根因：板上三套网络管理并存（systemd-networkd 早配 137.2 / connman 中后期可能接管 / **厂商晚到 setter 在开机后期一次性把 137.2 改回出厂 192.168.0.2**）。任何"只跑一次"的方案都发生在晚到 setter **之前**，抢不过。常驻 watchdog（每 15s 幂等自愈：发现 137.2 不在就夺回）越过该改写窗口，另配 connman 黑名单、去 netplan 同网段冲突、udev 覆盖热插拔。**通用套路**：有你不控制的主体在持续/晚到覆盖状态 → 用**幂等 watchdog**而非一次性脚本。 | ✅ | 无。归因（"晚到 + 在常规配置之后"）直接命中根因。 |

## R1 期间的追问与概念订正（非题库，但都是盲区）

| 追问 | 结论 | 备注 |
|------|------|------|
| `resize`/letterbox 代码在哪、改前改后是什么 | 修复在 commit `b7589cb`（vs 坏版 `0379f56`）；`infer_yolo_acl.py` 的 `preprocess()` L204-220、`postprocess()` L223-280 | 用 `git show` 看 `-/+` 判断"从什么改到什么" |
| 预处理到底在干嘛？为什么喂模型前必须变成 640×640？ | 预处理 6 步：等比缩放→补边→BGR2RGB→/255→HWC2CHW→返回。核心：**模型是"定形计算图"**，OM 由 ATC 编译时把 `1,3,640,640` 写死，640→(80,40,20) 网格正好拼出 8400 候选框；换尺寸=重新编译 | 预处理是"现实图片世界"与"模型只认固定张量"之间的唯一翻译层 |
| 现实车机也这样把 4K 缩到更小吗？ | 会，但**更早更硬件化**：`Sensor→MIPI→ISP→Scaler→NPU`，缩放/裁剪/格式转换在 ISP+DVPP 硬件上零拷贝完成，不占 CPU（本项目 R7 就是把预处理挪回硬件）。且车规常缩得**更保守**（960×540~1920×1080，甚至切片推理）以保远处小目标。逆映射扩展为"反缩放 + 去畸变 + 内外参投影 BEV" | toy pipeline = 量产链路的 CPU 简化教学版 |
| `NMSBoxes` 是什么？ | OpenCV 的 **NMS** 实现：从"同一物体的多个重叠框"里只留最高分。入参 `[x,y,w,h]`+分数+阈值，出参=**保留框的索引** | 只决定"留哪几个"，不改框内容、不画框 |
| 算 IoU 是什么意思？ | **IoU = 交集面积 / 并集面积** ∈ [0,1]，量两矩形重叠度。NMS：按分排序→取最高→删掉与它 IoU>阈值 的→重复 | IoU 虚高就会过度抑制 |
| **IoU 是不是就等于 anchor-based？** | ❌ **不是**。IoU 是一把**通用几何尺**（去重/训练匹配/评估都用）；anchor 是"**框怎么生**"的设计（anchor-based 在锚框上微调 / anchor-free 直接回归）。YOLOv8 是 anchor-free，但它的 NMS 照样用 IoU。**"用了 IoU" ≠ "anchor-based"** | 教科书讲 anchor 总配 IoU（用 IoU 给锚框分标签），那是 IoU 的一个用途，不是定义 |
